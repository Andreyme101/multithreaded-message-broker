# Multithreaded Message Broker

Дипломный проект: исследование производительности многопоточного брокера сообщений с ограниченной очередью. Реализован на C++ с использованием Boost.Asio, анализ результатов — на Python.

## Архитектура

```
Producer ──TCP──► Broker (BoundedQueue + Worker Pool)
                      │
                      └──► CSV / stdout метрики (раз в секунду)
```

**Broker** (`src/broker.cpp`) — TCP-сервер, принимает сообщения от продюсера, помещает в ограниченную очередь и обрабатывает пулом воркеров. Поддерживает два режима при переполнении очереди:

- `drop` — сообщение отбрасывается, инкрементируется счётчик потерь
- `block` — продюсер блокируется до появления места в очереди

**Producer** (`src/producer.cpp`) — TCP-клиент, генерирует сообщения с заданной интенсивностью (`--rate msg/s`), встраивает временну́ю метку `send_ns` для измерения latency end-to-end.

**BoundedQueue** (`include/bounded_queue.hpp`) — потокобезопасная очередь с ограниченной ёмкостью на основе `std::deque` + `std::condition_variable`. Поддерживает блокирующий и неблокирующий push/pop.

## Метрики

Каждую секунду брокер выводит и/или пишет в CSV:

| Метрика | Описание |
|---------|----------|
| `tps` | Обработанных сообщений за секунду |
| `mean_latency_ms`, `p50/p95/p99` | Задержка end-to-end (мс) |
| `drop_rate` | Доля отброшенных сообщений |
| `queue`, `max_queue` | Текущий и максимальный размер очереди |
| `rho_eff` | Эффективная загрузка системы (λ_eff / W·μ) |

## Сборка

**Зависимости:** CMake ≥ 3.15, Boost (asio), компилятор с поддержкой C++17.

```bash
cmake -S . -B build
cmake --build build --config Release
```

Или открыть `build/diplom.slnx` в Visual Studio.

## Запуск

Сначала запустить брокер, затем продюсер:

```bash
# Брокер: очередь=5000, воркеров=4, режим=drop, работа=5000 итераций
broker.exe --port 9000 --q 5000 --w 4 --mode drop --work 5000 --sec 15 --csv results/out.csv

# Продюсер: 600 000 сообщений/с, 16 секунд
producer.exe --host 127.0.0.1 --port 9000 --rate 600000 --sec 16
```

### Параметры брокера

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--port` | 9000 | TCP порт |
| `--q` | 5000 | Ёмкость очереди |
| `--w` | 4 | Количество воркеров |
| `--mode` | drop | Режим переполнения: `drop` или `block` |
| `--work` | 800 | Итераций синтетической нагрузки на задачу |
| `--sec` | 15 | Длительность эксперимента (сек) |
| `--batch` | 1 | Размер батча обработки |
| `--csv` | — | Путь к CSV-файлу результатов |
| `--csv-append` | false | Дописывать в CSV вместо перезаписи |
| `--rate-hint` | -1 | Rate продюсера (пишется в CSV для удобства) |

### Параметры продюсера

| Параметр | По умолчанию | Описание |
|----------|-------------|----------|
| `--host` | 127.0.0.1 | Адрес брокера |
| `--port` | 9000 | TCP порт |
| `--rate` | 20000 | Интенсивность посылки (сообщений/с) |
| `--sec` | 10 | Длительность генерации |

## Эксперименты

PowerShell-скрипты для воспроизведения замеров из диплома:

```powershell
.\run_rate_sweep.ps1                        # sweep по интенсивности
.\run_w_sweep.ps1                           # sweep по числу воркеров
.\run_drop_vs_block_q5000_w4_work5000.ps1   # сравнение режимов drop vs block
.\run_q_sweep_block_w4_work5000.ps1         # sweep по размеру очереди
```

После запуска — построить графики:

```bash
python analyze_rate_sweep.py
python analyze_w_sweep.py
python drop_vs_block.py
```

Готовые графики сохранены в `results/`.

## Структура проекта

```
├── src/
│   ├── broker.cpp       # брокер: TCP-сервер + очередь + пул воркеров
│   └── producer.cpp     # продюсер: генератор нагрузки
├── include/
│   ├── bounded_queue.hpp  # потокобезопасная ограниченная очередь
│   ├── net_proto.hpp      # структура сетевого сообщения
│   └── util.hpp           # now_ns() и прочее
├── build/               # CMake / Visual Studio проектные файлы
├── results/             # графики из экспериментов (PNG)
├── analyze_*.py         # скрипты анализа и визуализации
└── run_*.ps1            # скрипты запуска экспериментов
```
